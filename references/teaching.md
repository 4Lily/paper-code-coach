# 教学设计

## 项目与模块

- 新项目先明确研究问题、输入数据、目标产出和完成尺度。区分机制练习、最小端到端实现、与原项目对齐的复现和独立扩展。只介绍当前需要的库、环境与前置知识，先核实已有条件。
- 按可独立验证的功能拆模块。每个模块注明职责、输入输出、上游依赖和完成证据。起点优先选能观察核心机制、依赖少的一段。用户已指定入口时以该入口为准。
- 按用户要求覆盖章节。逐节讲解时保持原文顺序与编号，先解释该节承接的问题和新增结论，再展开相关公式、算法或实验。长篇且未要求一次讲完时，可先给简短目录并实质讲完第一组；明确本轮停在哪里。
- 进入实现模块时约定必要契约，例如输入输出含义、形状、类型、边界和两三个有辨识力的自查条件。若涉及简化，说明原设置、当前设置、保留的机制与恢复原行为需要补回的部分。允许等价实现和不同封装方式。
- 普通追问先解当前卡点。只在目标、依赖或范围变化时调整模块地图。

## 讲解与自主实现

以第一次打开项目的学员为读者。用同一份小样本串起三节，让学员能把手算的量认作函数的实参，再用手算结果检查自己的代码。备课时可参考[点云中心化短讲义](examples.md#点云中心化短讲义)。

### 一、原理与作用

交代模块在项目哪一步被调用，上游交来什么数据，当前遇到什么问题，下游需要什么结果。选一份能手算的输入，沿实际算法算到关键中间量和输出，解释每个变换解决的问题及成立条件。若练习简化了原项目，在此处指出差异。

首次出现的术语用当前样本解释，缩写给出全称。用到公式时，先定义符号、索引和每一轴，再对应到运算。涉及广播就列出对齐的形状，涉及归约就指出沿哪一轴聚合，涉及训练就讲清可训练参数与梯度边界。

### 二、函数用法

先给待实现函数的签名和一个调用示例，用上一节的样本说明调用方传什么、会得到什么。然后按首次使用顺序介绍步骤依赖的函数。逐个回答以下问题，简单调用可以用一两句话讲完。

- **从哪里获得，怎么调用？** 给出库的导入方式或项目辅助函数的导入路径。方法写明在哪类对象上调用、对象如何取得。陌生接口用独立的小输入展示一次可实际执行的调用。
- **参数分别控制什么？** 把调用中的实参与形参逐一对应，说明含义、当前值及选它的原因。类型、形状、单位、轴、取值范围或默认值会改变本例结果时，把它们讲清。
- **调用之后得到什么？** 用具体值说明返回类型、结构和形状，以及下一步怎样取值。遇到多个返回项就演示解包，遇到原地操作就指出哪个对象发生了什么变化、函数本身返回什么。

以当前版本的实际接口为准。代码围栏标注语言。若学员使用的缩写与源码有出入，指出实际符号，标明推测，必要时再请其提供所在行。

### 三、实现步骤

1. **找到落笔处。** 写出练习目录内的文件、目标符号和调用入口。点名已有对象或辅助函数的来源，以及本轮需要学员补全的部分。数据文件、配置或前置模块是运行条件时，讲清如何取得本例所需输入。
2. **按数据依赖拆解。** 把原理翻成有序操作。每步写清从参数或上一步取哪个量、用第二节哪个接口做什么、产物交给下一步哪里。对关键变换给出样本的中间值或形状。将组合操作和写出目标函数的工作留给学员，同时交代作出这些决定所需的规则。
3. **接回入口并自查。** 给出可执行的最小调用或现有测试命令，注明运行位置及预期返回值或可观察现象。选择能暴露典型错误的输入，说明出现哪种偏差时回查哪一步。区分手算预期和实测结果。

交付前，以第一次打开练习文件的顺序走读一次。遇到需要猜测的导入、变量来源、参数取值、实现动作或判断标准，就把缺的信息补到对应小节。原项目源码可供对照，讲义本身应提供完成练习所需的信息。

学员说「例子看懂了，函数还是写不出来」时，结合其尝试定位第一处断点。先让一个值或一行形状可观察，再按需要给更具体的 API 用法或不同输入的小例子，把提示写回原小节。用户明确要修复或完整代码时按请求交付。备课可查[例子](examples.md)，按当前学习目标选取片段。
